# Kolka Snapshot Download — Принцип работы

## Общая схема

Скрипт `kolka_snapshot_and_download.py` выполняется по расписанию (systemd timer).
При каждом запуске он последовательно обрабатывает все камеры из БД:

```
Для каждой камеры:
  1. BLE open → камера включает Wi-Fi точку доступа
  2. Ожидание (WifiWaitAfterOpen сек)
  3. Подключение к Wi-Fi камеры (nmcli)
  4. Снимок (cmd=1001 через HTTP API камеры)
  5. Загрузка полученного файла
  6. Сжатие JPG (если включено)
  7. Запись в БД (SnapshotLog + DownloadLog)
  8. BLE close → камера выключает Wi-Fi
```

## Блокировка

Используется файловая блировка `fcntl.LOCK_EX | fcntl.LOCK_NB` на файле `service.lock`.
Если скрипт уже запущен — второй экземпляр завершается с ошибкой.

## BLE (Bluetooth Low Energy)

### Подключение к камере

- Сканирование BLE-эфира через `BleakScanner.find_device_by_address()`
- Запись команды в характеристику `0000ff11-0000-1000-8000-00805f9b34fb`
- Таймаут сканирования: `BleScanTimeout` (по умолчанию 10 сек)
- Таймаут подключения: `BleCommandTimeout` (по умолчанию 10 сек)

### Команды

| Команда | Действие |
|---------|----------|
| `open`  | Включить Wi-Fi точку доступа камеры |
| `close` | Выключить Wi-Fi точку доступа |

### Сброс адаптера

При ошибке `InProgress` (адаптер занят) выполняется сброс:
```bash
hciconfig hci0 down
sleep 1
hciconfig hci0 up
sleep 2
```

## Wi-Fi подключение

### Порядок подключения

1. `nmcli connection down id {SSID}` — отключить если есть
2. `nmcli connection delete id {SSID}` — удалить профиль
3. `nmcli connection add type wifi ...` — создать профиль с паролем
4. `nmcli connection up id {SSID}` — подключиться

### Повторные попытки

- При неудаче: повторная отправка BLE `open` + ожидание `WifiWaitAfterOpen`
- Количество попыток: `WifiMaxRetries` (по умолчанию 5)
- Таймаут каждой попытки: `WifiConnectTimeout` (по умолчанию 90 сек)

## Снимок (cmd=1001)

### HTTP API камеры

- Базовый URL: `http://192.168.1.254/`
- Endpoint: `/?custom=1&cmd=1001&par=0`
- Ответ: XML с тегами `<STATUS>`, `<NAME>`, `<FPATH>`

### Пример ответа

```xml
<?xml version="1.0" encoding="UTF-8 ?>
<Function>
  <Name>1001</Name>
  <Status>0</Status>
  <Photo>
    <NAME>2026-0729-135227_000058.JPG</NAME>
    <FPATH>A:\DCIM\PHOTO\2026-0729-135227_000058.JPG</FPATH>
  </Photo>
</Function>
```

### Парсинг пути

```
A:\DCIM\PHOTO\2026-0729-135227_000058.JPG
  ↓
Убрать A:\, заменить \ на /
  ↓
DCIM/PHOTO/2026-0729-135227_000058.JPG
  ↓
URL: http://192.168.1.254/DCIM/PHOTO/2026-0729-135227_000058.JPG
```

## Загрузка файла

- Скачивание через HTTP GET (`aiohttp`)
- Сохранение в `DownloadPath` (по умолчанию `/outgoing/cameratrap/`)
- Имя файла: `{CamId}_{YYYY-MM-DD-HH-MM-SS}.{ext}`
- Пример: `1_2026-07-29-13-52-27.JPG`

## Сжатие изображений

После загрузки JPG/JPEG файла (если `CompressAfterDownload=true`):

1. Вызывается `compress_images.py` на папку с загруженным файлом
2. Скрипт находит все JPG, пропускает уже сжатые (`_cmp_` в имени)
3. Сжатие через `ffmpeg -i input.jpg -q:v {quality} output.jpg`
4. Качество: `CompressQuality` (по умолчанию 12, диапазон 1–31)
5. Оригиналы удаляются после сжатия

## Логирование

### Файлы

- Паттерн: `logs/snapshot_download_log_{YYYY-MM-DD}_{HH}.log`
- Новый файл каждый час
- Ротация: logrotate (ежедневно, 14 дней, gzip)

### БД

- `SnapshotLog` — запись о каждой попытке снимка (успех/ошибка, время, попытки)
- `DownloadLog` — запись о каждой загрузке (успех/ошибка, размер файла, путь)

## Обработка ошибок

### BLE open не удался

- Повторные попытки: `MaxRetriesPerCamera` (по умолчанию 3)
- Задержка между попытками: `RetryDelay` (по умолчанию 15 сек)
- Если все попытки исчерпаны — переход к следующей камере

### Wi-Fi не подключился

- Повторные попытки: `WifiMaxRetries` (по умолчанию 5)
- Перед каждой попыткой: повторная отправка BLE `open`
- Если все попытки исчерпаны — переход к следующей камере

### Снимок не удался

- Повторные попытки: `WifiDownloadRetries` (по умолчанию 3)
- При неудаче — запись в SnapshotLog с ошибкой

### Загрузка не удалась

- Повторные попытки: `WifiDownloadRetries` (по умолчанию 3)
- При неудаче — запись в DownloadLog с ошибкой

## Калибровка (calibration.py)

### Предусловие

При запуске проверяет: если все поля (Name, MacAddress, WifiSSID) заполнены
**И** количество камер ≥ `CamerasCount` — выходит без действий.

### Фаза 1: Обнаружение камер (BLE)

1. Сканирует BLE-эфир на устройства `GCBT40`
2. Для каждого устройства проверяет уникальность `MacAddress` в БД
3. Записывает `Name` и `MacAddress` в таблицу `PhotoTrap`
4. Повторяет до достижения `CamerasCount` камер

### Фаза 2: Привязка Wi-Fi SSID

1. Для каждой камеры без `WifiSSID`:
   - Отправляет BLE `open` → камера включает Wi-Fi
   - Сканирует Wi-Fi сети на `CAM_*`
   - Записывает найденный SSID в БД
   - Отправляет BLE `close`
2. Повторяет до заполнения всех камер

### Уникальность

- `MacAddress`: UNIQUE constraint в БД (`PhotoTrap_MacAddress_key`)
- `WifiSSID`: проверка на уровне приложения (запрос перед insert/update)

## Конфигурация (config_loader.py)

### Цепочка приоритетов

```
БД (PhotoTrapConfig)  →  Файл (appsettings.json)  →  Дефолты (DEFAULTS)
```

### Загрузка

1. Запрос всех строк из `PhotoTrapConfig`
2. Чтение `appsettings.json`
3. Сборка результата: для каждого ключа берётся значение с наивысшим приоритетом
4. Парсинг типов: числа → int/float, булевы → bool, JSON-строки → dict

### Сохранение

Функция `save_config_to_db()` позволяет сохранить параметры в БД.
Если ключ уже существует — обновляет значение, иначе создаёт новый.
